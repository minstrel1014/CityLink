Purpose: the previous coordinator and Role 6 evidence was gathered on a disposable PostgreSQL **16.15** engine, while both target projects run **17** (Test `wkzclgmhrtecnpexfesr` 17.11.0.011, Main `pijslbchvstkoweslymr` 17.11.0.003). ## How 17 was provisioned in this sandbox

The sandbox's configured apt sources ship only `postgresql-16`; `apt-cache policy postgresql-17` was empty until the PostgreSQL PGDG repository was added. The supported route, recorded here so any owner can reproduce it:

1. fetch `https://www.postgresql.org/media/keys/ACCC4CF8.asc` and de-armour it to `/usr/share/postgresql-common/pgdg/apt.postgresql.org.gpg`;
2. add `deb [signed-by=…] https://apt.postgresql.org/pub/repos/apt noble-pgdg main` (Ubuntu 24.04.5, codename `noble`);
3. `apt-get update` then `apt-get install postgresql-17`, which resolved to **17.12-1.pgdg24.04+1**.

The packaged cluster was never used. The probe created its own data directory under `/tmp`, ran `initdb -A trust --no-sync`, and started the server with `-c listen_addresses=''` plus a `/tmp` unix socket directory, so there were **zero TCP listeners** (`ss -ltn | grep -c 543` → `0`). The server was stopped with `-m fast`, the data directory and socket directory were deleted, and `pgrep -c postgres` returned `0` afterwards. No Supabase endpoint was contacted, no credential was read, and no `.env` file exists in this sandbox.

The one difference worth stating plainly is that the first F10 capture on 17 truncated its own evidence: `head -2` printed the column header and the rule but not the row, which could be misread as "nothing survived". The focused re-run removed the ambiguity and is the number quoted above. That is exactly the class of mistake the real-parser gate exists to catch, so it is recorded rather than quietly corrected.

## What this does and does not establish

It establishes that the engine-level claims used to justify the F7/F8/F10 findings are true on the target major version, not merely on the version that happened to be installed. It does **not** establish anything about Test or Main contents, privileges, RLS, function bodies, application rows, authentication or concurrency: those need the separately authorized read-only Test dry run and, later, the authorized signed-in QA.

It also does not resolve the successor instrument by itself. Adam chose option (b) at 22:04 — a SELECT-only preflight plus a thin refusal wrapper — so the 608-line guard is not repaired and F7/F8 are retired by construction. This spot-check still matters under option (b), because the preflight's own digest and normalization expressions must behave identically on 17, and because any residual `::regclass` or `search_path` comparison that survives the reshape has to be tested the same way.

## Reproduction

The probe script is archived in the same commit as this document. To reproduce: install `postgresql-17` from PGDG, replace the script's `PGBIN` with `/usr/lib/postgresql/17/bin`, and run it as the `ubuntu` user with `sudo` available for the `postgres` account. The script creates and destroys its own cluster, leaves no listener and no process behind, and prints the engine version first so that any future run states which major version produced its numbers.
