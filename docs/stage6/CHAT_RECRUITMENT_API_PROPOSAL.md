## Human-approved behavior recorded for this proposal

The approved Stage 6 baseline remains: group chat is private to group members; active and former members may read history, but only active members may send, and pending invitees/join-requesters have no chat access. Sending is blocked for abandoned groups; active members may still send in archived groups. Messages are immutable in v1. ## Proposed SQL artifact

[Revision 2 proposal-only SQL draft](CHAT_RECRUITMENT_MIGRATION_PROPOSAL.sql) contains the revised DDL, indexes, RPC-only access, helper functions, RPC signatures/bodies, grants, lifecycle functions, and triggers. It remains a design artifact, not a migration; the proposal itself has not been executed, and this task made no Supabase query. Role 6 reports offline parser checks for the supplied v2 source (63 top-level statements, 13 PL/pgSQL functions, 6 SQL-language function bodies). This task has not rerun those parser checks after adding the closed-post authorization predicate, and static parsing is not PostgreSQL or live Test validation.

The draft proposes:

1. `public.group_chat_messages`: immutable plain text, sender ID nullable for account deletion, sender-name snapshot, group FK `ON DELETE RESTRICT` so history is not silently purged with group deletion, and a group/time/key index.
2. `public.group_recruitment_posts`: group/course/term, nullable author ID, author-name snapshot, body, `open|closed`, timestamps, composite FK to the group/course/term, and indexes. No delete endpoint is proposed.
3. Group/member/profile discovery functions: `list_current_term_course_groups(p_course_id,p_after_group_name,p_after_group_id,p_limit)` returns only forming/active groups in the current term with at least two active membership rows; pending invitations do not count. Defaults to 25 rows, maximum 100, and returns `has_more`. `list_current_term_group_members(p_group_id,p_after_joined_at,p_after_membership_id,p_limit)` and `get_current_term_group_member_profile(p_group_id,p_profile_id)` require a current-term forming/active group with at least two active members. Roster/profile eligibility follows the existing any-shared-course audience, not current-term same-course enrollment. The member list returns only `profile_id` as a non-display selector, approved profile attributes, cursor fields, and `has_more`; the profile detail returns only approved profile attributes plus the selector. No raw membership rows are returned.
4. Chat functions: `get_group_chat_access(p_group_id uuid)` returns `can_read`/`can_send`; `list_group_chat_messages(p_group_id,p_before_created_at,p_before_id,p_limit)` pages history; and `send_group_chat_message(p_group_id,p_body)` sends plain text. Active/former group members may read while the group record exists. Active members may send except in abandoned groups; active members may send in archived groups. Pending invitees/requesters are denied. Messages have no update/delete endpoint.
5. Recruitment functions: `list_group_recruitment_posts(p_course_id,p_after_created_at,p_after_id,p_limit)` defaults to 20 rows, maximum 100, and returns `has_more`; create/edit/close RPCs remain `create_group_recruitment_post`, `edit_group_recruitment_post`, and `close_group_recruitment_post`. Reading requires current-term course enrollment. Post results include viewer-specific `apply_enabled` and author-only `can_manage`. Apply requires an open post, active current-term group, enrolled viewer with profile status `open` or `considering`, no active membership in that course/term, and no pending invitation/request for that group; Roy’s request RPC remains final enforcement. Membership end and archived/abandoned group status close open posts. Manual and automatic closure are read-only, including for an active author; no reopen RPC is provided. Archived/abandoned posts remain visible but return no group ID/name/member count and have no Apply/edit/close action.
6. Both new tables have RLS enabled, no direct table policies, and no client table grants (including `SELECT`). Field-limited `SECURITY DEFINER` RPCs are the only client API. No anon access or direct DML. Every RPC/helper pins an empty `search_path`, schema-qualifies relations/functions, and rechecks authorization; identifiers never bypass checks. Role 6 and Roy must verify table/function ownership, helper execution, private-schema exposure, and lifecycle integration before any migration can be considered.

The SQL draft proposes technical text bounds of 4,000 characters for messages and 2,000 for posts; these values still require feature-owner review. Its archived/abandoned behavior follows Adam’s v2 direction: eligible current-term readers can still see the post text, author snapshot, and closed status, while group selectors/name/member count are null and all Apply/edit/close actions are disabled. The new roster audience deliberately preserves the existing broad any-shared-course rule without changing the direct `profiles` policy or legacy classmate RPC.

## API contract summary for review

| Operation | V2 contract | Authorization |
| --- | --- | --- |
| List course groups | `list_current_term_course_groups(p_course_id,p_after_group_name,p_after_group_id,p_limit)` → `group_id`, `group_name`, `group_status`, `active_member_count`, `can_create_post`, `has_more`; default 25, max 100 | Authenticated viewer enrolled in the requested course in the configured current term; only forming/active groups with at least two active membership rows; pending invitations do not count |
| List group members | `list_current_term_group_members(p_group_id,p_after_joined_at,p_after_membership_id,p_limit)` → `profile_id`, approved profile fields, `cursor_joined_at`, `cursor_membership_id`, `has_more`; default 50, max 100 | Group is current-term forming/active and has at least two active members; viewer/member follow the existing any-shared-course audience; return active members only |
| Open member profile | `get_current_term_group_member_profile(p_group_id,p_profile_id)` → `profile_id` and approved profile fields | Group is current-term forming/active with at least two active members; target is an active member; viewer and target share any course under the existing profile audience |
| Check chat access | `get_group_chat_access(p_group_id)` → `can_read`, `can_send` | Active/former group members may read; only active members may send, and not when group status is abandoned; active members may send in archived groups |
| Load chat history | `list_group_chat_messages(p_group_id,p_before_created_at,p_before_id,p_limit)` → message ID, sender-name snapshot, text, timestamp | Active or former membership while the group record exists; no course-term check for former history |
| Send chat message | `send_group_chat_message(p_group_id,p_body)` → message ID | Authenticated active group membership; abandoned group, former members, pending invitees/requesters denied |
| Browse recruitment posts | `list_group_recruitment_posts(p_course_id,p_after_created_at,p_after_id,p_limit)` → post, author snapshot, status, permitted group summary, `apply_enabled`, `can_manage`, `has_more`; default 20, max 100 | Authenticated current-term course enrolment; archived/abandoned group posts remain visible but closed and group summary/action fields are withheld |
| Create/edit/close post | `create_group_recruitment_post(p_group_id,p_body)`, `edit_group_recruitment_post(p_post_id,p_body)`, `close_group_recruitment_post(p_post_id)` | Create as eligible active member of an active current-term group. Edit/close only an open post by its active author. Closed posts (manual or automatic) are read-only; no reopen/delete/report endpoint |
| Apply | Roy’s `requestToJoinGroup(userId,groupId)` wrapper calling `request_to_join_group(p_group_id)` | UI flag requires open post, active current-term group, viewer enrolled with profile status `open` or `considering`, no active membership in that course/term, and no pending invite/request; Roy’s RPC remains final enforcement |
